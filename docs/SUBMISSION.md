# Submission pack

Everything needed to submit Brain Blitz as a YouTube Playable, minus the parts
that require portal access.

> **Unverified specs.** `developers.google.com` is blocked from the environment
> this was prepared in, so exact character limits and image dimensions could not
> be read from the certification pages. Copy below is written to several lengths
> so something fits whichever limit applies, and the art is generated at common
> sizes with a script that can produce any other. Anything needing confirmation
> is marked **[verify]**.

---

## 1. Build the upload

```bash
npm ci
npx playwright install chromium
npm run build          # -> dist/brain-blitz-playable.zip
```

All the game code, data, styling, fonts and music are in `index.html` at the
archive root (the fonts are embedded and the music is synthesised, so there are
no media files). The bundle is **545 KB zipped**. The page itself is 385 KB.
The rest is the in-game icons in `assets/icons/` (about 100 KB of 128 px PNGs),
plus the launcher icons and manifest, which ride along only so the page's
`<head>` links resolve inside the player. The build fails rather than
producing a bundle if a size cap is exceeded, and it finishes by launching the
built file and playing a round, so what you upload is what was tested.

| Limit | Budget | Bundle |
|---|---|---|
| Initial payload | 30 MiB (15 MiB recommended) | 1.8% of the cap |
| Total bundle | 250 MiB | negligible |
| Per file | 30 MiB (512 KiB recommended) | 385 KB, the page |

## 3. Art

Generated by `npm run art` from `tools/keyart.html`, in the game's own style:
its blue, Lilita One with the navy outline (the fonts are lifted from
`index.html`), and the in-game icons. The wide art shows the feature chips and
a stack of Block Blitz blocks; the square tile is the bolt over the title. The
script refuses to write a file if the background, the font or any image fails
to render.

| File | Size | Use |
|---|---|---|
| `art/keyart-1280x720.png` | 1280×720 | 16:9 store art |
| `art/keyart-1920x1080.png` | 1920×1080 | larger 16:9 |
| `art/icon-512.png` | 512×512 | square listing tile |
| `art/icon-1024.png` | 1024×1024 | larger square listing tile |

Any other size: `node tools/make-art.js 1600x900`. **[verify the required
dimensions and file formats in the portal and regenerate.]**

### Launcher icons

A separate set, generated by `npm run icons` from the vector mark in
`tools/logo.js`. These are what a phone shows when the page is added to a home
screen; the listing tiles above carry a wordmark and are unreadable at that
size. They ship inside the bundle so the page's own `<head>` links resolve
rather than 404 inside the player, though nothing at run time reads them.

| File | Size | Use |
|---|---|---|
| `icons/apple-touch-icon.png` | 180×180 | iOS home screen |
| `icons/icon-192.png` | 192×192 | Android launcher, manifest |
| `icons/icon-512.png` | 512×512 | Android splash, manifest |
| `icons/icon-maskable-512.png` | 512×512 | Android adaptive mask, manifest |
| `icons/favicon-32.png`, `favicon-16.png` | 32, 16 | browser tab |
| `icons/favicon.svg` | vector | browser tab, any size |
| `manifest.webmanifest` | — | name, colours and icon list |

`tests/icons.test.js` reads the pixels back out of each file, so a silent render
failure fails the suite instead of shipping.

### Content notes

900 questions, reviewed for a 13+ general audience:

- No profanity, sexual content, gambling or self-harm references.
- Alcohol references were removed, though nothing suggests they are
  disqualifying — a general-audience title with questions to spare does not need
  the reviewer to make a judgement call.
- History includes the World Wars, the Holocaust diary of Anne Frank and the
  American Civil War, handled factually and neutrally, as school curricula do.
  Flagging in case a reviewer reads them differently.
- Facts that decay were avoided deliberately: no current record holders, heads
  of state or "most X ever" questions whose answer can be overtaken. Where a
  superlative is used it is a settled physical fact (largest planet, deepest
  ocean point).

## 6. What still needs you

1. **Submit the interest form** using §5. Everything it asks for exists today,
   and approval reportedly takes weeks to months, so submitting early is the
   single highest-value thing left.
2. **Read the certification pages** and settle every **[verify]** above.
3. **Run the bundle in the portal's test harness.** This is the first contact
   with YouTube's real runtime rather than a mock, and is the true verification
   of the SDK integration.
4. **Decide what `sendScore` should report for the new modes.** It currently
   reports quiz and daily scores. Block Blitz scores are on a different scale,
   so check how the portal uses the value before sending them too.
